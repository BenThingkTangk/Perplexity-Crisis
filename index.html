GUIDED SCENE // THE CLOUDFLARE WALL
LIKELY · TLS / UA fingerprint ASK · Akamai Bot Manager compatibility lab

A Comet user hits a Cloudflare-protected site — and never gets through.

Community-reported pattern on Perplexity's public Discord (May 24–29, 2026). Comet fails Cloudflare bot-detection on third-party sites and gets stuck on the challenge page across devices and networks. This is a Comet third-party-site compatibility signal — not a statement about Perplexity's own routing.

  1. 01 Open Comet User opens Comet desktop and navigates to a high-traffic third-party site behind Cloudflare bot mitigation.
  2. 02 Cloudflare challenge page Cloudflare presents a verification interstitial (Turnstile / BotFight). Comet's TLS / user-agent fingerprint trips a bot signal.
  3. 03 Challenge loop · no recovery Verification never completes. User is permanently walled. Reproduced across devices and networks per the public Discord thread.
  4. 04 Same site loads in Chrome / Safari Mainstream browsers pass the same challenge cleanly — isolating the signal to Comet's custom-browser fingerprint, not the user.
  5. 05 Akamai compatibility lane Akamai Bot Manager + Client Reputation use different signals. A partner-grade allow-list could whitelist Comet on Akamai-protected sites — needs Akamai lab confirmation.

Narrative for the meeting: Cloudflare's bot-detection treats your own browser as a bot. Akamai's edge gives you a place to negotiate browser identity — without touching your AWS / Foundry / CoreWeave compute graph.

Meeting questions · grouped

What to ask Perplexity. Grouped, precise, neutral.

Discovery questions across seven lanes — routing, Comet / Cloudflare, cache, auth + billing, observability, enterprise SLA, and API gateway. Each accordion expands for the verbatim list. No assumptions about Perplexity's internal routing are baked into the questions.

Routing & traffic management 4 questions
  1. How many CDN / edge providers are currently in your stack, and what is the traffic split across them?
  2. On the May 7 incident where Website and API both degraded, was the root cause traced to an edge layer, origin, or a control-plane configuration change?
  3. What is your current failover SLA, and how is traffic shifted when an origin region degrades — DNS-TTL based, or a real-time traffic manager?
  4. Are CDN configurations differentiated for the web product, Sonar API, and Comet browser traffic?
Comet · Cloudflare compatibility 3 questions
  1. Are you aware that Comet is failing Cloudflare bot-detection challenges on third-party Cloudflare-protected sites per multiple community reports? What is the plan — fingerprint normalization, or CDN-side compatibility negotiation?
  2. Has Comet been tested for compatibility with Akamai-protected sites? Akamai Bot Manager + Client Reputation use different signals; a partner-grade allow-list lane may be feasible.
  3. Is Comet performing any SSL interception or non-standard certificate manipulation that might cause failures at sites using EV certificates or HSTS preloading?
Cache strategy 2 questions
  1. What percentage of perplexity.ai traffic is cacheable at the edge (static assets, popular results, image-gen outputs) vs pure origin / inference?
  2. Have you explored edge-caching for high-frequency identical queries (trending topics), and if so, what is the cache invalidation strategy?
Auth & billing 2 questions
  1. Community reports include double-charges and silent annual-default after pause/resume. Is the billing microservice behind an API gateway with idempotency enforcement, or is it exposed directly?
  2. How do you handle session token invalidation at the edge when a user's subscription state changes (Pro → cancelled → resubscribe)?
Observability & incident telemetry 3 questions
  1. Your May 7 status sequence showed an auto-resolve / re-open loop. Is status automation tied to synthetic checks, real user monitoring, or manual updates?
  2. Do you have per-region, per-endpoint RUM today? What is your P95 latency target for inference streaming?
  3. Are #status and #bug-reports signals from your public Discord being ingested into your incident management pipeline, or is that manual?
Enterprise SLA 2 questions
  1. Enterprise customers in the public Discord report 2+ week support response gaps. What is your contracted enterprise incident-response SLA, and how is it enforced?
  2. Would you be open to a dedicated Enterprise-tier edge configuration giving your largest customers guaranteed path priority and dedicated health checks?
API gateway 2 questions
  1. Is the Sonar API behind the same API gateway as the web product? Status incidents show they can degrade independently.
  2. What is the current rate-limit strategy for Sonar — IP, token, or account-based? Are you seeing false-positive rate-limiting against legitimate enterprise API consumers?
